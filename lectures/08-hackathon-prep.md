# 08. ハッカソン助走

## ハッカソンのルール

### 期間
- 最終日(金曜16時まで)
- 最終日午後に発表(一人5~10分)

### お題
- **自由**。
- 思いつかない人は、AI研修でやった「AI幹事に旅行を任せたい」やってみてください。

### 個人戦
- 1人で1つのアプリを作る
- 質問は自由
- 一時的にペアで詰まりを解くのもOK
- 「コードを書くのは自分」 を守ればOK

### スターターリポジトリ
- Next.js 16 + TypeScript + Tailwind + ESLint
- 1機能だけ (例: シンプルなユーザープロフィール) が実装済み
- これを fork して、自分のアプリに育てる

---

## AI レビュー (`/review-nextjs`) の使い方

自分の書いたコードを AI にレビューしてもらいます。
ターミナルで:

```bash
claude
```

を起動して、対話画面で:

```
/review-nextjs
```

と打ちます。すると `docs/code-review-checklist.md` の観点 (Next.js 16 の API / Server·Client 境界 / キャッシュ整合性 / セキュリティなど 8項目) に沿ってレビューが走り、 結果がMarkdownが返ってきます。

このマークダウンを元に修正を入れてください。

## ストレッチ要件 (余裕があれば)

- 認証連携 (NextAuth.js など)
- 楽観的更新 (`useOptimistic`)
- キャッシュ戦略の意図的使い分け (`cacheTag` 活用)
- E2E テスト (Playwright)
- メタデータ最適化 (動的 OG 画像)
- `Suspense` + `loading.tsx` での体験向上
- ダークモード対応
- レスポンシブ対応

## アイデア出し

issueに以下のように何を作るのか書き出してください。

1. **お題**: 「○○管理アプリ」など
2. **MVP**: 「これだけ動けばOK」 を1〜2行
3. **主要画面 3つ**: URL とそこに何を表示するか
4. **データ構造**: モデル名 と主要フィールド (3〜5個)
5. **作成・更新のフロー**: フォームから何を入れて、何を保存するか

### 例 (読書記録アプリ)

```
お題: 読書記録
MVP: 読んだ本のタイトル + 感想を保存し、一覧で見返せる

画面:
  /         → 本一覧 (タイトル + 評価)
  /books/[id] → 本の詳細 (感想 + 編集ボタン)
  /books/new  → 新しい本を追加するフォーム

データ:
  Book {
    id, title, author, rating(1-5), memo, createdAt
  }

フロー:
  /books/new で title, author, rating, memo を入力 → 保存 → 一覧へ
```
