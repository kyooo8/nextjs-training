# 08. ハッカソン助走

> **60分 (お題決め + フィードバック)**
> Day 3 朝に走り出せる状態を作る回。コードは書きません。お題を決めて、講師の軌道修正を受ける時間です。

## この章のゴール

- ハッカソンのルールと必須要件を理解する
- 自分の **お題** が決まっている
- 講師から「スコープ大きすぎ」「ここは削れる」のフィードバックを受け終わっている

---

## なぜこの章があるか

ハッカソン最大の失敗パターンは **「機能を盛り込みすぎて完成しない」** です。
1人で 3日 で動くものに収めるには、講師の目で **スコープを切る** のが効きます。
「自分なりに考えて → 講師に話す → 削る」 のサイクルを、ここで1周回します。

---

## ハッカソンのルール

### 期間
- **Day 3 朝 〜 Day 5 午後**
- 最終日午後にデモ大会 (1人 3分、画面共有)

### お題
- **自由**。自分が「使いたい」と思えるものが一番
- 思いつかない人は、後ろのテンプレ集から選んでOK

### 個人戦
- 1人で1つのアプリを作る
- ただし **質問は自由** (講師は常駐、Slack あり)
- 一時的にペアで詰まりを解くのもOK
- 「コードを書くのは自分」 を守ればOK

### スターターリポジトリ
- Next.js 16 + TypeScript + Tailwind + ESLint
- 1機能だけ (例: シンプルなユーザープロフィール) が実装済み
- これを fork して、自分のアプリに育てる

### 講師
- 常駐
- Slack `#nextjs-training-2026` で質問
- 5分悩んだら聞いてOK

## 必須要件 (これだけは何があっても満たす)

| # | 要件 | 学習章 |
|---|------|--------|
| 1 | ルートが **3画面以上** (一覧・詳細・作成 or 編集) | 02 |
| 2 | Server Component でのデータ取得が **1箇所以上** | 04 |
| 3 | Server Actions での書き込みが **1箇所以上** | 05 |
| 4 | テストを **1つ以上** 書く (Vitest or Playwright) | 07 |
| 5 | 自分のお題で **手元で動くものがある** (デプロイ不要) | — |

5番が一番大事です。**動くものが手元にある** = ハッカソン成功。

---

## ストレッチ要件 (余裕があれば)

- 認証連携 (NextAuth.js など)
- 楽観的更新 (`useOptimistic`)
- キャッシュ戦略の意図的使い分け (`cacheTag` 活用)
- E2E テスト (Playwright)
- メタデータ最適化 (動的 OG 画像)
- `Suspense` + `loading.tsx` での体験向上
- ダークモード対応
- レスポンシブ対応

> 💡 ストレッチ要件は **絶対やらなくていい**。必須要件を満たすのを優先。

---

## スコープを小さく保つコツ

### MVP (Minimum Viable Product) を定義する

「これだけ動けば自分にとっては嬉しい」を1行で書く。
例: 「読んだ本のタイトルと感想を保存できて、一覧で見返せる」

これを満たす機能だけ作る。**それ以外は最後まで残す**。

### 見た目より機能

Tailwind で「それっぽく」は作れます。
凝った CSS は最後の30分で。

### 完成優先

**7割完成 (動くデモ可能) > 3割の野心作 (バグだらけ)**。
人に見せられる状態を Day 4 夕方には作って、Day 5 で磨きをかける流れがオススメ。

### CRUD 全部やらなくていい

最低限 **C (作成) + R (読み込み)** があれば良いです。
U (更新) と D (削除) は時間があればで。

## アイデア出しタイム (15分)

紙やテキストエディタに、以下を書き出します。

1. **お題**: 「○○管理アプリ」など
2. **MVP**: 「これだけ動けばOK」 を1〜2行
3. **主要画面 3つ**: URL とそこに何を表示するか
4. **データ構造**: モデル名 と主要フィールド (3〜5個)
5. **作成・更新のフロー**: フォームから何を入れて、何を保存するか

### 例 (読書記録アプリ)

```
お題: 読書記録
MVP: 読んだ本のタイトル + 感想を保存し、一覧で見返せる

画面:
  /         → 本一覧 (タイトル + 評価)
  /books/[id] → 本の詳細 (感想 + 編集ボタン)
  /books/new  → 新しい本を追加するフォーム

データ:
  Book {
    id, title, author, rating(1-5), memo, createdAt
  }

フロー:
  /books/new で title, author, rating, memo を入力 → 保存 → 一覧へ
```

これを **15分で書き上げる**。完璧でなくてOK、後で講師と話して直します。

## 1分プレゼン (講師に聞いてもらう)

書いたものを元に、1人ずつ 1分で講師に説明:

- お題
- MVP (1行)
- 機能3つ (これ以上盛り込まない)

講師から:
- 「スコープ大きすぎ、ここは削れる」
- 「この機能は1時間で実装できる/3日かかる」
- 「○○の章を見直すといい」

のフィードバックを受けます。**素直に削るのが正解** です。

## 詰まったら (Q&A)

**Q. お題が思いつかない**
A. テンプレ集から「自分の生活で困っていること」 で選ぶ。「使いたい」が大事。

**Q. スコープが大きすぎる気がする**
A. MVP を **半分** にしてみる。「これだけ動けば嬉しい」 のラインを下げる。

**Q. 認証を入れたい**
A. ストレッチ要件です。**最後の半日まで触らない**。 必須要件を満たしてから。

**Q. DB は何を使えばいい?**
A. スターターに入っているもの (SQLite + Prisma など) をそのまま使うのが速いです。新しいものに手を出すと環境構築で半日溶けます。

**Q. デプロイは必要?**
A. **不要**。「手元で動く」がゴール。やりたい人は Vercel が一番速い。
