# /review-nextjs

このプロジェクトは Next.js 16 研修 / ハッカソンの提出物です。
**`docs/code-review-checklist.md` の観点に厳密に沿って** コードレビューを行ってください。

## レビュー対象

次のすべてを対象に:

1. 未コミットの変更 (`git status -s` と `git diff` の出力)
2. ブランチが `main` から分岐してから現在までのコミット差分 (`git log main..HEAD --stat` と `git diff main..HEAD`)

`git` リポジトリでない場合は、`lectures/` を除く `src/` 配下のソース全体を対象にしてください。

## 守るべき手順

1. **まず `@docs/code-review-checklist.md` の中身を完全に読む** (観点 1〜8 の Bad ❌ / Good ✅ をすべて頭に入れる)
2. **次に `@docs/nextjs-docs-cheatsheet.md` の中身も読む** (Next.js 16 の現行 API を確実に把握)
3. レビュー対象のファイルを 1ファイルずつ読む (推測で書かない、必ず Read する)
4. 観点 1〜8 のチェックを順に当てる
5. 該当する違反があれば、**ファイルパス + 行番号 + 該当コード + 修正案** をセットで記録
6. 観点表の末尾「レビュー結果の出力形式」 に厳密に沿って Markdown を出力

## 重要な注意

- **観点表に書かれていない指摘は基本しない** (好みの主張ではなく、観点に基づく事実ベース)
- **古い Next.js の知識 (Next.js 14 までの API) で指摘しない**。`@docs/nextjs-docs-cheatsheet.md` の対応表を必ず確認
- **「良かった点」 も2〜3個書く** (改善点だけ並べるレビューは新卒のモチベーションを削る)
- **修正案は具体コードで示す** (「〜したほうがよい」 ではなく「こう書く: `...`」)
- **Must / Should / Nice to have の区別を厳密に守る** (全部 Must にしない)

## 出力の最後に

レビュー結果は **そのままハッカソン提出物に貼り付けられる形** で出力してください。
別途、受講者向けに 1〜2文 で「次に何をすればよいか」 のコメントを最後に添えてください。

これらを守って、レビューを開始してください。
